# 头像按钮拨错人：焦点恢复改写悬停目标

用户反馈任务栏头像旁的语音通话连续拨给其他人。此前 0.1.49 为解决 Windows 吞掉点击，将浮窗改为可聚焦；这暴露了页面把焦点恢复当作悬停选择的旧路径。上一轮测试覆盖按钮命令和原生激活决策，没有覆盖“上次聚焦乙、现在悬停甲、窗口重新激活”的组合。

## 已复现的原因

旧 DockAvatar 的 onFocus 与 onMouseEnter 共用 open，恢复到乙头像的原生焦点事件会在 80ms 后将 hovered 改为乙。所有人的卡片复用同一批按钮 DOM，而 act 在 click 时读取 hoveredRef.current。按下甲的按钮后焦点恢复 / 计时器触发，松开时就发送乙的 ID。

- 浏览器离线夹具：按下甲的“看屏幕”，恢复乙头像焦点，再松开，得到 `[watch,p2]`，卡片也变为乙。
- Windows 原生夹具：使用生产 createDockWindow 与两个独立测试窗口，实际切换前台 / 恢复焦点；旧构建悬停甲后恢复焦点，卡片变为乙，命令为 `[call,p2]`；新构建保持甲并发送 `[call,p1]`。
- 邀请桥和服务端沿用传入 socket ID，没有将工位编号或名单索引用于收件人。游客、无工位成员不是此问题的原因。

## 修复

- useDockHover.ts 管理悬停计时器和输入来源。只有明确 Tab 导航产生的焦点变化才切换预览，原生窗口恢复焦点不切换；指针操作和窗口失焦清除键盘导航标志，保留键盘操作。
- DockPreviewCard.tsx 的三个按钮显式绑定 person.id，不再读取全局悬停 ref。卡片以 person.id 为 React key，换人时创建新的按钮，防止在旧按钮按下、在替代人的按钮上完成点击。
- 关闭卡片、发起邀请、打开状态 / 会议、拖放文件时清除旧开关定时器。头像到卡片内部的焦点移动不再误排关闭。
- 卡片尖按 data-person-id 定位头像，不通过可重复的显示名字定位。显示布局、三个按钮的右侧位置、权限和邀请确认语义保持现有实现。
- dock.tsx 拆分后 418 行，预览组件 46 行、悬停 Hook 44 行；没有改原生主进程、后端协议或安装器。
