# 分享者屏幕绿色边框（2026-10-16）

需求：分享者一眼看出自己正在共享哪块屏幕，效果参考会议软件的绿色细边框。

## 行为与源码

- `OfficeDesktop/share-border.cjs`：每块正在共享的显示器一个透明窗口，按完整
  `Display.bounds` 定位（包含负坐标、副屏、缩放、任务栏区域）；仅边缘 3 DIP 绿色实线。
  无文字、无闪烁、不抢焦点、不占任务栏，整窗鼠标穿透。
- 使用 `setContentProtection(true)` 请求 Windows 将提示层排除在捕获画面之外。
  插拔、分辨率、DPI 变化时重贴；退出、主窗口关闭、主页面跳转/重载、渲染进程崩溃时销毁。
  最小化或收进托盘不等于停止共享，不能把框藏掉。
- 原有 `preview-glow` 继续只负责“有人来看你”的短暂绿光，语义没有合并。
- `OfficeWeb/src/screenShareIndicator.ts`：捕获结束时固定每条轨的真实显示器来源，克隆轨继承来源；
  发布成功才登记提示，取消发布/停止/结束时释放。私聊、会议和主动公共预览共用登记表。
  多条共享在同一屏幕只显示一圈，停止一条不会消掉另一条仍在共享的提示。
- 换屏按实际发布结果更新：失败保留原屏框；部分房间换屏成功、部分失败时，两个仍在发送的屏幕
  都有提示。单纯改预览屏幕选项不会挪动正在共享的框。
- `MediaStreamTrack.stop()` 不触发 `ended`，因此仅在有共享轨时每 250ms 清掉已结束轨；
  显示器集合没变化不发 IPC、不重建窗口。最后一条轨释放后停止计时器。
- 浏览器和旧客户端缺少此原生能力时，沿用原有系统共享提示，不阻止共享。

## IPC 契约

仅可信主窗口/主框架可调用，沿用 `desktop-bridge.cjs` 的来源校验。

| 通道 | 请求 | 返回与含义 |
| --- | --- | --- |
| `office:captured-display` | 无 | 最近一次授权捕获的真实 `display_id`，不取当前选项 |
| `office:sharing-displays` | `string[]`，最多 32 项 | `boolean`；原生仅接受本页面已经捕获过的 ID，空列表清框 |

preload 暴露 `officeDesktop.screenShareIndicator.source/show`，类型同步在 `desktop.d.ts`。
高清采集统一经 `captureScreen`：不把并发捕获排队到用户手势过期后，而是提示稍后重试；
锁保持到来源回执拿到为止，避免两次采集串用来源。没有改变权限检查、没有自动接听。

## 同时修复的换屏问题

LiveKit `LocalTrack.replaceTrack()` 会修改包装器持有的 `mediaStreamTrack`。
会议首次换屏后原先的 `capture.tracks.forEach(track => track.stop())` 会停掉刚换上的画面。
改为替换前记录旧的原始轨，替换成功后只停这些旧轨。测试模拟 SDK 包装器真正改变引用，
旧代码复现“右屏刚换上就 ended / 绿框消失”，新代码保持新发布轨 `live`。
