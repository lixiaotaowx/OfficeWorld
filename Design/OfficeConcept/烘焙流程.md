# OfficeWorld 最新贴图烘焙流程

更新：2026-09-13，已对照当前烘焙、降噪、导出脚本及九台显示器进度清单复核。以本流程作为后续增量烘焙的操作依据。
显示器修复实例见 [Monitor_Rebake_20260913.md](Monitor_Rebake_20260913.md)。

## 流程总览

**保存当前现场副本 → 确定增量对象 → 检查网格与源材质 → 每物体独立 Bake_UV → 256 采样烘焙 Radiance / Albedo / Normal → 对烘焙图执行引导降噪 → 临时贴回真实模型验收 → 保存清单与工程 → 导出副本统一换图 → Draco / WebP → 网页近景与正式站验收。**

本次最新成功烘焙仍是九台显示器的 1K / 256 采样 / 6 px 扩边版本，清单为 `total=9`、`done=9`、`finished=true`、`errors=[]`。
之后的网页窄边框是加载时修改内沿几何，没有重新烘焙，不能将它记录为新的烘焙批次；详见文末。

## 1. 确认工程与备份

- 当前工作工程：`AssetSources/OfficeConcept/备份_独立UV烘焙_20260912.blend`。
- 先读取 Blender 实际打开的文件路径，确认用户最新修改已经在当前工程中。
- 修改前用另存副本保存当前现场，包括尚未保存的用户修改；不要只复制磁盘上的旧文件。
- 每次使用新的备份名称，不覆盖上一次备份。用户的模型外形、布局和灯光调整应保留。
- 显示器本轮备份：`备份_显示器重烘焙前_20260913.blend`。
- 检查没有正在运行的烘焙队列，禁止重复启动。

## 2. 选择对象与贴图尺寸

每个需要烘焙的物体独占 UV 空间、独立贴图，逐个处理，不把多个物体一起展开或一起烘焙。
只重烘焙本轮需要修改的对象。模型、UV 或材质变化会使其旧烘焙失效；如影响周围阴影或反弹光，还需检查相邻物体。

| 对象 | 建议起点 |
|---|---|
| 地面、主要桌面 | 2048 × 2048 |
| 近看设备、墙面或中等物件 | 1024 × 1024 |
| 不重要的小物件 | 512、256 或更小 |
| 纯色细小零件、玻璃、透明件、动态屏幕 | 按需免独立光照贴图 |

- 按实际画面占比、UV 利用率与近景质量决定尺寸，不统一上大图。
- 本轮九台显示器从 512 提升至 1K，改善底座边缘；其他物体不跟着扩大。
- 键盘采用简单盒体与共用键盘图，不恢复复杂键帽和逐台光照图。

## 3. 先检查网格，再展开 UV

1. 检查重叠面、异常法线、极小碎片，以及位置重合但未连接的顶点。
2. 导入资产可能把连续表面拆成许多断开的三角面；直接智能展开会得到大量碎 UV 岛。
3. 仅在确认应连续的表面上焊接重合点。不得盲目合并薄壁、不同部件或有意断开的边。
4. 本轮显示器的合并距离为模型坐标下 `0.000001`，每台由 1116 顶点变为 309，外形保持一致。该数值不是所有资产的通用阈值。
5. 共享网格如需独立 UV，先复制网格数据，使每个对象拥有自己的 UV。
6. 取消其他物体选择，只激活当前物体；进入编辑模式选择全部面。
7. 对 `Bake_UV` 使用 **Smart UV Project（智能 UV 投射）**，不是多物体 Lightmap Pack。

本轮显示器参数：角度 66°、岛间距 0.035、Correct Aspect 开启、Scale to Bounds 开启。
检查岛间距与分辨率、烘焙扩边是否匹配；不要因扩边过大污染相邻 UV 岛。

- 普通带原始纹理的物体：保留原始 UV，源纹理通过显式 UV Map 节点使用原始 UV，烘焙明确指定 `Bake_UV`。
- 本轮纯色显示器：旧 UV 不再承担源纹理，才移除旧层，只保留 `Bake_UV` 并设为活动渲染 UV。
- 不要把“删除其他 UV”推广到所有带贴图资产。
- 对照真实尺寸检查木纹方向、织物尺度和纹理拉伸；烘焙本身不会修复源纹理比例。

## 4. 源材质与烘焙目标分开

- 显示器外壳和底座使用简单 **Principled BSDF（原理化 BSDF）→ Material Output**。
- 本轮基色为浅暖灰白，线性 RGBA `(0.72, 0.70, 0.65, 1)`，金属度 0，粗糙度 0.55。
- 不需要纹理的纯色部件不添加噪声、凹凸、混合或发光节点。
- 其他有必要的原始 PBR 材质保留，不一概改成纯色。
- 为当前对象创建独立目标图像；每个材质槽内的活动 Image Texture 节点都指向该图像。
- 目标节点约定名：`BAKE_OUTPUT_UNCONNECTED`。放在节点编辑器空白处，**不要连接到着色器**。
- 烘焙整批完成之前，全部物体保持源材质参与光照，不逐个把烘焙图贴回去。
- 旧工程若存在 `BAKED_PREVIEW_SOURCE_BOUNCE` 等预览混合节点，烘焙前切回源着色器，断开烘焙图的输出连接。

## 5. 逐物体烘焙与真正的图像降噪

- 渲染器：Cycles；采样不得低于 **128**，当前质量基准为 **256**。
- `use_selected_to_active = False`；明确使用 `Bake_UV`；目标清空后烘焙。
- 本轮 1K 显示器的烘焙扩边为 **6 px**。其他尺寸需检查调整。
- `cycles.use_denoising = True` 保持开启，但这个开关本身不是烘焙输出已降噪的证据。

每个物体依次生成三张相同尺寸、相同 UV 的浮点临时图：

| 图像 | 烘焙方式 |
|---|---|
| Radiance | COMBINED，DIRECT / INDIRECT / DIFFUSE / EMIT |
| Albedo | DIFFUSE，仅 COLOR |
| Normal | NORMAL，OBJECT 空间，图像设为 Non-Color |

将 Radiance、Albedo、Normal 分别接到合成器 Denoise 的 Image、Albedo、Normal 输入。
使用 **High 质量、Accurate 预滤波、HDR 开启**，再输出 PNG。
这一步是在处理烘焙图像本身，不是仅给最终场景渲染降噪。
上述 Radiance 通道适用于当前静态漫反射光照方案，不等同于烘焙所有镜面反射和玻璃效果。

处理图像的辅助场景使用 Standard、Look None、Exposure 0、Gamma 1，避免额外烘入显示变换。
当前脚本保存的是 **8 位 RGBA PNG**；PNG 编码无损，不代表保存了浮点 HDR 原始通道。三张输入图为浮点临时图，处理后会释放。如果后续需要重新降噪或调整曝光，应在新批次额外保存浮点原始通道，不能假定旧批次全部留存了这些输入。
完成当前对象后保存 PNG，更新目标图像节点但不连接它，释放无用临时图，再处理下一个对象。
任何对象失败均记录错误并停止该队列，不能把部分完成状态当作整批成功。

## 7. 实际贴图验收

- 必须把烘焙结果临时应用到相同 UV 上看近景，不能用原理化源材质的漂亮渲染代替贴图验收。
- 本轮 `preview_monitors.py` 临时以烘焙图连接发光显示，防止重复受光；渲染结束恢复简单源材质。
- 检查底座接缝、边缘、桌下阴影、墙面、地板，以及颜色、木纹和织物细节。
- 碎裂或花斑优先排查：断开顶点、碎 UV 岛、UV 层不一致、扩边污染、尺寸不足、旧图回灌。
- 源材质正常而烘焙图异常时，不要仅增加灯光或采样掩盖 UV 问题。

## 8. 导出网页与线上复核

1. 全部目标完成后，在临时导出副本上统一应用烘焙图，源工程保持可编辑材质。
2. 导出副本使用求值后的网格，包含修改器最终结果，避免修改器覆盖材质槽。
3. 烘焙副本只保留 `Bake_UV` 并设为活动渲染 UV；保留工位、屏幕等自定义属性。
4. 导出 `OfficeWeb/public/assets/office-baked.glb`，保留 extras、使用 Draco；清理临时副本并恢复现场。
5. 当前工具以 JPEG 85 为导出中间图，再将 GLB 内图像压缩为 WebP 72；源 PNG 不受影响。压缩后仍需检查边缘与细节。
6. 网页烘焙材质按已有光照显示，避免再乘动态光照和阴影；动态人物及免烘焙物体单独照明。
   当前 `bakedMaterials.ts` 使用 `MeshBasicMaterial`，烘焙图按 sRGB 读取，`toneMapped=false`；不要只因纹理看起来偏亮就再次套用 AgX。合成降噪输出的 Standard 设置和导出副本的显示变换不是同一步，导出前应记录实际源场景的 View Transform / Look / Exposure，并以 PNG、导出 GLB、网页三者对照确认没有重复变换。
7. 更改资源版本号，构建至 `Build/OfficeWeb`，按 [部署文档](../Deployment.md) 上传实际资源与前端入口。
8. 最终目标仅为 **https://115.159.43.237/**。比对模型 SHA256，刷新并查看真实场景近景；本地导出不代表上线。

## 9. 现有工具及使用边界

脚本目录：`tools/office-concept/`。

- `prepare_monitor_rebake.py`：现场备份及显示器简单材质准备；有备份存在保护，不可无脑重复执行。
- `fix_monitor_uv.py`、`weld_monitor_uv.py`：本轮纯色显示器的 UV / 拓扑处理，不用于全场景批量套用。
- `rebake_monitors.py`：九台显示器增量烘焙，最终参数 1K / 256 / 6px。
- `denoise_bake_images.py`：实际图像降噪辅助场景。
- `preview_monitors.py`：临时应用烘焙图并渲染近景。
- `export_selective_web.py`、`compress_web_bake.py`：导出与压缩，压缩脚本只对新导出的 GLB 执行一次。
- 旧 `bake_individual_uv.py` 中的低采样初版参数仅为历史，不符合正式质量要求，不能直接当最新流程运行。
- MCP 客户端超时不代表 Blender 任务失败；先检查进度、输出更新时间与运行标志，禁止直接重复启动。

## 10. 下一批次的执行顺序与完成判定

这些脚本包含日期目录、九台显示器筛选和备份保护，是已验证实例，不是可对任意场景直接重复执行的一键工具。新批次先设置新的输出目录和备份名，核对对象清单；不要为了让断言通过而删除旧备份。

| 顺序 | 使用的现有逻辑 | 执行前后要确认的内容 |
|---|---|---|
| 1 | `prepare_monitor_rebake.py` | 确认实际打开的工程；保存当前现场副本；目标节点不接入着色器 |
| 2 | `fix_monitor_uv.py` / `weld_monitor_uv.py` | 根据具体资产选用；本轮最终智能展开参数为 66° / 0.035，不能停留在准备脚本中的 0.025 |
| 3 | `rebake_monitors.py` | 正式参数为 1024 / 256 / 6 px；主场景 Cycles 设备沿用现场设置，执行前确认实际设备可用 |
| 4 | `denoise_bake_images.py` | 由烘焙脚本调用；辅助场景设为 GPU，三张图必须同尺寸、同 UV、来自同一物体 |
| 5 | 进度与输出检查 | 检查 `current`、`done`、`errors`、`finished`，以及实际 PNG 文件存在、尺寸正确、可读取 |
| 6 | `preview_monitors.py` | 用实际烘焙图作无重复受光的近景；结束后确认源材质与现场设置已恢复 |
| 7 | `export_selective_web.py` | 所有目标通过后才导出；先做本批 GLB 备份；核对 Bake_UV、extras、修改器结果与图像节点 |
| 8 | `compress_web_bake.py` | 只压缩新导出版本一次；保留源 PNG；比较压缩前后纹理、文件体积与实际近景 |
| 9 | 构建与发布 | 按部署文档上传实际构建和资源，再核验正式站版本及画面 |

完成烘焙必须同时满足：

- `finished=true`，`errors` 为空，`done` 数量与计划对象数一致。
- 每个完成项的贴图文件实际存在，尺寸与清单一致；不能仅信任 `denoised=true` 字段。
- `office_bake_running` 已清除；超时后先检查它和文件更新时间，不重复启动队列。
- 实际贴回烘焙图的近景合格，检查的不只是源材质视图。
- 源工程保存，目标图像节点指向最终结果；源材质没有误接旧烘焙图再次参与下一轮照明。
- 烘焙成功、导出成功、压缩成功和正式站发布成功分别记录，不合并为一个“完成”。

## 11. 本轮窄边框与后续重烘焙的关系

2026-09-13 的实体窄边框由网页 `monitorBezel.ts` 在加载时克隆并修改网格：只移动内沿顶点，原 UV、法线、材质、支架和机身外轮廓保留。原 GLB 与用户 Blender 工程未改动，此项没有产生新贴图。

- 这是已作近景检查的局部几何适配，不能据此推断任意网格变化都可继续使用旧烘焙。
- 如果以后要把窄边框正式落到 Blender 资产，应在独立副本中按最终尺寸改模，再检查 UV、阴影和源材质后执行本流程。
- 导出新模型后检查网页的内沿适配：不得对已经收窄的模型再缩一遍；重新核对屏幕尺寸、边框与点击命中。
- 若改变支架、机身位置或灯光，需评估桌面接触阴影与邻近物体反弹光，一并加入增量重烘焙清单。
