# 景深评估（2026-09-13）

本轮暂不启用景深，也不增加无效果的设置开关；不阻塞顶部、显示器和通信修复。

## 当前实现证据

- `OfficeWeb/src/OfficeScene.tsx` 使用 WebGLRenderer 直接渲染到画布。
- 像素比上限 1.5，已启用抗锯齿、阴影与 AgX 色调映射。
- 当前 src 没有 EffectComposer、BokehPass 或 DepthTexture 管线。
- 每帧直接调用 renderer.render(world, camera)。

## 为什么暂缓

景深需要额外颜色/深度纹理和模糊合成，不能通过相机焦距属性直接获得。
需要同时处理抗锯齿、色调映射、窗口尺寸变化与资源释放。
显示器文字在三维场景内，必须验证对焦与屏幕边缘保护；仅保持 DOM 清晰不够。

以 1440×900、像素比 1.5 为例，单张 RGBA8 缓冲约 11.1 MiB。
两张颜色缓冲加一张按 4 字节计的深度缓冲，约 33.4 MiB；
这是示例配置的理论估算，未含多采样、驱动开销或其它渲染资源，
不是当前程序已分配量，也不是完整景深方案的显存实测。

尚未在目标设备测量新增 GPU 耗时，因此不能认定开销低或满足轻量目标。
按用户允许的边界，本轮保留直接渲染，不改场景入口。

## 后续接受条件

- 可选、默认关闭；关闭时不保留额外渲染目标和逐帧处理。
- 同设备同视角比较关闭/开启的帧耗时和显存，覆盖低端设备。
- 目标显示器文字清晰，旋转、缩放和选择工位时焦点稳定。
- 正确处理玻璃、墙体裁切、曝光、抗锯齿和尺寸变化。
- 任一条件不满足就不发布此可选效果。
