# 私人来电角色与状态栏通话控制

## 问题与修复

- 原来私人来电只靠每 3 秒补发的临时 greeting；悬停 watched 可以覆盖正在响铃的角色。私人邀请不在缓存的 dock 状态里，窗口重载不能直接恢复；共享时还可能被原生共享隐藏规则挡住。
- 新增 `DockPrivateState`：传递待接听邀请、私人会话与操作状态，主窗口仍唯一拥有 Socket 和媒体。邀请状态变化立即推送，并保留原来的心跳。原生桥限定字段、数量和文本长度，缓存后用于浮窗首帧恢复。
- 来电舞台优先显示真实待接听私人邀请，其次会议邀请，再次悬停提示。语音、看对方屏幕、分享自己的屏幕都显示发起人的招手角色与头顶接听 / 拒绝按钮。取消 / 拒绝 / 超时 / 接通后随邀请清理；晚到的旧 greeting 不能重新弹出。初始异步快照不能覆盖已收到的新状态；新 requestId 重新播放招手并重建接听按钮。
- `DockCallControls` 复用会议的两种控制样式：共享保留文字，麦克风仅图标，静音显示红色斜线。私人命令使用会话 ID，校验会话仍连接，重复操作串行；会议激活时不操作私人媒体。多条私人会话分别标识对方。
- 私人通话或来电期间，即使已经共享屏幕也保留头像条；手动隐藏、任务栏位置与外部全屏避让仍由原生窗口现有规则决定。
- `private-share` 和 `private-mute` 经现有受信 IPC 路由回主窗口。只有有效的开始共享点击，或接听有效的“看你的屏幕”邀请，才赋予主窗口 5 秒、一次性、绑定接收窗口的捕获点击意图；停止共享、静音、拒绝和过期请求都不赋予。沿用桌面端已选物理屏幕的捕获方式，没有改成自动接听。

## 验证

- 网页专项 28/28，私人信令 / 游客 / 无工位场景 4/4，桌面全量 173/173；构建及 90 项资源一致性检查通过。
- 浏览器以离线桥加载实际构建及正式站资源，三种邀请均量到真实 `招手_Wave` 动画、角色腕部运动、头顶按钮位置与命中区。无 greeting 心跳时持续显示，悬停其他人不会顶掉来电；旧初始快照与晚到来电事件不恢复过期请求。忙碌状态禁用重复操作，共享 / 静音状态与指定会话命令匹配，结束后清理。
- 正式资源普通刷新后，私人来电 / 控制、既有会议布局 / 控制与三按钮目标身份回归均通过。
- Windows 原生隔离窗口分别以源码和最终 ASAR 跑过：6 个原有邀请按钮、头顶接听、私人共享 / 静音及两个测试窗口间的真实焦点恢复；命中区关闭穿透，命令 ID 正确。四个相关 ASAR 原生模块与源码逐字节相同。
- 用例早期失败：动画断言误写成 `Wave`；原生夹具固定 250px 高没有模拟来电扩窗，状态转换后未等待布局、鼠标仍停在原位置。纠正夹具后通过，没有将这些失败描述成用户现场问题。
- 未拨打真实同事、未进行真实音频 / 屏幕采集或双机人工验收。原生测试使用独立测试窗口及 `sendInputEvent`，不等同于物理鼠标与真实双机通话验收。
